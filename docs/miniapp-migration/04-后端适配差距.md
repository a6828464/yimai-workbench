### 1.2 小程序侧能力边界（一手文档核实，全部来自 2026-11-03 抓取）

官方来源：
- `https://developers.weixin.qq.com/miniprogram/dev/api/network/request/wx.request.html`（及同页 `.md`）
- `https://developers.weixin.qq.com/miniprogram/dev/api/network/request/RequestTask.onChunkReceived.html`
- `https://developers.weixin.qq.com/miniprogram/dev/framework/ability/network.html`
- `https://developers.weixin.qq.com/miniprogram/dev/framework/release/v2.html`（基础库更新日志）
- `https://raw.githubusercontent.com/wechat-miniprogram/api-typings/master/types/wx/lib.wx.api.d.ts`（微信官方 GitHub 组织的官方 typings）

| 待核实问题 | 官方结论（原文） | 判定 |
|---|---|---|
| `wx.request` 有分块能力吗 | `enableChunked`：boolean，默认 false，「开启 transfer-encoding chunked」，**最低基础库 2.20.2** | 有，但有版本门槛 |
| 逐块回调存在吗 | `RequestTask.onChunkReceived(listener)`：「监听 Transfer-Encoding Chunk Received 事件。当接收到新的chunk时触发」，**基础库 2.20.1 起**；回调 `res.data` 类型 **ArrayBuffer** | 有 |
| 能拿到什么 | 只有 `ArrayBuffer` 原始字节。**没有任何 SSE 解析**：没有 `data:` / `event:` / `[DONE]` 语义，没有自动解码 UTF-8 分帧 | 需自己实现解码 + 行切分 + 跨块粘包处理 |
| 关监听 | `RequestTask.offChunkReceived(listener)`，2.20.1 | 有 |
| 是否仅 HTTPS | 是，且不止「仅 HTTPS」：`wx.request`「发起 **HTTPS** 网络请求」；域名必须 `https`、**必须 ICP 备案**、**不能用 IP/localhost**、**不能配父域名**、**端口必须精确匹配**（配了 `:8080` 就只能打 `:8080`；不配端口则连 `:443` 都不能出现在 URL 里） | 「仅 HTTPS」成立，且约束比 HTTPS 更严 |
| chunked 与 HTTP/2 关系 | 「除声明了 `enableChunked` 后会走 **HTTP1** 以外，均会自动开启 HTTP2/HTTP3」 | 开 chunked 会强制回落 HTTP/1.1——这恰好是 chunked 传输的前置条件，不是缺陷 |
| 会不会被后台打断 | 「小程序进入后台运行后，如果 **5s** 内网络请求没有结束，会回调错误信息 `fail interrupted`」 | **致命**：AI 生成 10–60s，用户切后台必断 |
| 并发 | `wx.request`/`uploadFile`/`downloadFile` 最大并发 **10** | 够用 |
| timeout | 单次默认 **60000ms**，可在 `app.json` `networkTimeout.request` 或调用参数覆盖（`timeout` 参数 2.10.0 起） | 非流式必须显式放大，否则 60s 砍断（后端上游允许 120s，`AiController.php:124`） |
| Header 限制 | `header`「**header 中不能设置 Referer**」，其格式固定 `https://servicewechat.com/{appid}/{version}/page-frame.html` | Bearer 头可设，Referer 不可伪造成 web 端行为 |
| 开 chunked 后 `res.data` 还给不给全量 | **官方文档未说明**。`success` 里 `data` 字段仍定义为「开发者服务器返回的数据」 | **【待实测】** 不能假设「既拿 chunk 又拿全量」 |

**结论（对「保留流式但小程序侧消费」的直接回答）**：技术上**可以**逐块拿到字节（≥2.20.2，HTTPS，HTTP/1.1），但官方**只给 ArrayBuffer**，SSE 协议解析要自建；叠加「后台 5s 断流」「无标准 SSE 语义」「iOS/Android 行为差异待实测」三条，这条路是**高成本 + 高不确定性**，不适合作为 M2 的第一版。

### 1.3 三个方案

| 维度 | ① 降级为非流式（推荐） | ② 轮询任务化 | ③ 保留流式但小程序不消费 |
|---|---|---|---|
| 做法 | 小程序调 `/api/ai/chat` **不带** `stream`，拿 `{code:0,data:{content}}` | `POST /api/ai/chat/jobs` 受理 → `GET /api/ai/chat/jobs/{id}` 查状态 → 取 `content` | 后端 `AiController.php:161` 原样保留；小程序端**不提供** AI 生成入口（AI 只用 web） |
| 后端改动 | **0 行**（`AiController.php:188-197` 就是这条路） | 新增 2–3 端点 + 1 张 job 表 + 复用 `SyncJob` 异步范式（约 4–6 人日） | 0 行 |
| 小程序改动 | 1 个 `apiPost` + loading 骨架 | 受理/轮询/取结果 3 段 + 轮询退避与超时兜底 | 0（功能不做） |
| 首字延迟 UX | 差（10–40s 白屏，必须骨架屏 + 进度文案） | 中（受理即返回，进度可显示但无逐字） | 不涉及 |
| 体验天花板 | 固定 | 固定 | — |
| 风险 | ① 60s 默认超时需显式放大（`AiController.php:124` 上游 120s）；② 长响应被用户切后台 5s 断流同样适用；③ 逐字动画彻底失去 | ① 需幂等 + 僵尸回收（可抄 `BackupController.php:287-316`）；② `fastcgi_finish_request` 在非 php-fpm（如 CLI/其他 SAPI）不存在，须保留同步兜底（`BackupController.php:313` 已有 `'background' => function_exists('fastcgi_finish_request')` 先例）；③ 轮询频次与 `throttle:120,1`（`bootstrap/app.php:33`）叠加 | AI 能力在小程序缺位，产品叙事要提前对齐 |
| 工作量 | **0.5 人日**（前端接入 + 超时调参 + 骨架屏） | 4–6 人日 | 0 |
| 阻塞 M2 | 需要 1 个决策，不需要改造 | 会挤压 M2 | 需要产品侧确认 |

### 1.4 推荐：①（非流式），并把 ② 留作「体验不达标时的升级路径」

理由（按权重排序）：

1. **后端零改动就有一条成立的路**——`AiController.php:188-197` 已经是完整实现，`stream` 缺省 `false`（`117` 行），说明「非流式」从来不是降级补丁，而是原生支持的第二种模式。这使 ① 的成本/风险比远优于 ②③。
2. **① 的 UX 损失是可控的**：一麦的 AI 用途是「生成朋友圈/小红书文案、训练计划」，产物是一段文本，不是对话流；骨架屏 + 「正在生成，约 20 秒」即可覆盖。而 ③ 会让小程序缺功能。
3. **② 的唯一优势（进度可见）在 5s 后台断流面前也保不住**：真正的流式才需要 ② 的进度感；一旦放弃逐字，② 的复杂度（新表、新端点、崩溃恢复、幂等）换不来对应收益。
4. **② 的复用成本其实不高**，所以不作为「不做」，而作为「先不做」：`sync-jobs` 的受理→轮询范式在仓库里已经跑通并有前端实现（`admin-web/src/views/yimai/sync/index.vue:435-470`，4s 轮询 + 130 分钟兜底 + 单次失败不中断），一旦 ① 的等待体验被用户否决，照抄这套即可。

**决策点（需 captain/用户拍板）**：M2 是否接受「AI 生成无逐字动画、最长约 40s 白屏（有骨架屏）」。接受 → ① 落地，工作量 0.5 人日；不接受 → 走 ②。

### 2.2 `wx.request` 携带 `Authorization: Bearer` 可行吗

**可行，且这是官方支持的正规做法。**

- `wx.request` 的 `header` 参数：Object 类型，官方唯一禁止项是 **Referer**（「header 中不能设置 Referer」）——`Authorization` 不在禁止之列。来源：`https://developers.weixin.qq.com/miniprogram/dev/api/network/request/wx.request.html`（2026-11-03）。
- 同一条限制也适用于 `wx.uploadFile` / `wx.downloadFile` 的 `header`（两者文档措辞一致：`官方 doc`，2026-11-03）。
- 无 Cookie/Session 依赖：本项目是纯 Bearer（`sanctum.php:40` `'guard' => ['web']` 但 API 走 `auth:sanctum` token 认证，未启用 `statefulApi()`，`bootstrap/app.php` 全文无该调用），所以小程序端不涉及 cookie 域问题。

**注意**：Referer 不可改这件事有副作用——后端 `LogApiRequest` 中间件记录 UA/Referer 时，小程序流量的 Referer 恒为 `https://servicewechat.com/{appid}/{version}/page-frame.html`（官方原文）。若运维侧有「按 Referer 拦非浏览器流量」的规则，小程序会被误伤。**这是运维层要检查的一条**（本次未在仓库中找到此类规则，`DEPLOY.md` 无 nginx 片段）。

### 2.3 `registerSessionExpiredHandler` 能否照搬

**模式可以照搬，触发点不能照搬。**

web 端现状（`admin-web/src/api/backend.ts:11-28`）：模块级单例 + `sessionExpired` 闩锁 + `sessionExpiryInProgress` 在途 Promise 去重 + 清 token → 调 handler（`main.ts:33` 注册为 `useUserStore().logOut()`）+ 登录成功时 `setBackendToken` 复位闩锁（`backend.ts:30-33`）。这是**正确的、可复用**的去重设计（避免 10 个并发 401 触发 10 次登出）。

但触发来源在两端完全不同：

| 环节 | web（axios） | 小程序（wx.request） |
|---|---|---|
| 4xx/5xx 走哪个分支 | `response` 拦截器的 **error** 分支（`backend.ts:72-86`），401 在此命中 | **`success` 回调**——官方原文：「只要成功接收到服务器返回，**无论 `statusCode` 是多少，都会进入 `success` 回调**」（`framework/ability/network.html`，2026-11-03） |
| 401 识别方式 | `error.response?.status === 401` | 必须自己 `if (res.statusCode === 401)` |
| 竞态去重 | 靠 `requestToken !== currentToken` 判断「token 已换过，忽略这次 401」 | 逻辑可原样保留，但**要放在 request 侧保存本次 token 快照**（`wx.request` 不会回传 request header） |
| 完成回调 | `finally` | `complete`（成功失败都执行） |

**照搬时必须新增的一道闸门**：`statusCode` 先行判定。否则 401/403/422/429/500 全部落进 `success`，详见 §5.4 的「静默判成功」矩阵。

### 2.4 是否需要新增 refresh 端点

**结论：不需要。**理由：

1. 现状 `refreshToken === token`（`AuthController.php:41`），说明「refresh」这个词在系统里是**占位**，没有任何轮换语义；新增 refresh 端点等于凭空造一套双 token 机制，与 Sanctum 的 `expiration` 模型冲突（Sanctum 的过期判定基于 `created_at`，`Guard.php:128`，不看 `last_used_at`——除非开 `trackLastUsedAt` 并改判定）。
2. 一麦是**内部员工工具**（账号由管理员在「人员管理」开通，自助注册默认关闭，`AuthController.php:48-53`），14 天过期 + 重新输入密码是可接受的成本；web 端现在就是这么做的（`logOut()` 后回登录页）。
3. 真正需要「无感续期」的场景在 §2.5 的 `wx.login` 静默登录里被更好地解决：**静默登录本身就是续期通道**——401 时先尝试 `wx.login` 换新 token，失败才弹密码。

**若仍要「滑动续期」**，最小改动是「登录态保活端点」而不是 refresh：`POST /api/auth/touch` 删旧 token + 发新 token（响应形状同登录），由小程序在「距上次使用 > 7 天 且 用户活跃」时调用。工作量 1 人日。**不推荐进 M2**。

### 2.5 `wx.login` + `code2session` 后端端点设计

#### 2.5.1 前提（一手文档核实）

| 前提 | 官方原文 | 判定 |
|---|---|---|
| 接口必须服务端调用 | 「接口应在**服务器端调用，不可在前端（小程序、网页、APP等）直接调用**」（`/server/API/user-login/api_code2session`，2026-11-03） | 小程序端不可直连 |
| `api.weixin.qq.com` 能配白名单吗 | 「**出于安全考虑，`api.weixin.qq.com` 不能被配置为服务器域名，相关 API 也不能在小程序内调用。** 开发者应将 **AppSecret 保存到后台服务器中**」（`framework/ability/network.html`，2026-11-03） | **强制**走后端代理；AppSecret 必须留服务器 |
| code 生命周期 | 「用户登录凭证（有效期**五分钟**）」；「临时登录凭证 code **只能使用一次**」（`wx.login` + `framework/open-ability/login`） | 必须一次性消费，不能缓存复用 |
| session_key 能不能下发 | 「开发者服务器**不应该把会话密钥下发到小程序，也不应该对外提供这个密钥**」（`framework/open-ability/login` 注意事项 1） | 只存服务端，不进响应体 |
| 接口签名 | `GET https://api.weixin.qq.com/sns/jscode2session?appid=APPID&secret=SECRET&js_code=JS_CODE&grant_type=authorization_code` | 4 个 query 参数，`grant_type` 固定 `authorization_code` |
| 返回字段 | `openid` / `session_key` / `unionid`（绑开放平台才有）/ `errcode` / `errmsg` | 注意：`errcode:0` 也出现在成功示例里，判定要写成 `errcode` 缺省或为 0 |
| 错误码 | `-1` system error / `40029` code 无效 / `40226` 高风险用户被拦截 / `45011` 分钟级配额超限 | 必须逐条映射成可读中文 |

#### 2.5.2 端点契约（草案）

```
POST /api/auth/wx-login          （免登录，throttle:20,1 独立桶）
body: { "code": "<wx.login 拿到的 code>" }
res 成功: { "code":0, "data": { "token":"<sanctum plainTextToken>", "refreshToken":"<同 token>",
                               "userInfo":{...同 AuthController::userInfo()} , "bound": true } }
res 未绑定: { "code":1, "message":"该微信尚未绑定员工账号，请先用账号密码登录后绑定" , "needBind": true }  // HTTP 200，保持 {code,message} 家族
res 失败:   { "code":1, "message":"微信登录失败（40029 code 无效），请重试" }  // HTTP 200，code 走业务码
```

设计要点（每条都对着一个具体风险）：

1. **响应形状必须与 `/auth/login` 完全一致**（`AuthController.php:37-44`），否则小程序侧要写两套登录后处理；`refreshToken` 保持与 `token` 同值以维持现有语义占位。
2. **不做「来了就建账号」**：小程序是内部工具，`openid` 必须先绑定到既有 `users` 行。绑定流程建议单独端点 `POST /api/auth/wx-bind`（需登录，body `{code}`）——先账号密码登录 → 再 `wx.login` 绑定。这一步不做，等于给任何扫码进入小程序的人开一个员工账号。
3. **AppSecret 托管位置**：`backend/.env` 的 `WECHAT_MINIAPP_APPID` / `WECHAT_MINIAPP_SECRET`，经 `config('services.wechat_miniapp.*')` 读取（对齐现有 `config/services.php` 的 `registration` 写法，`AuthController.php:49` 就是这么取的）。**绝不进**：小程序代码、`admin-web` 的 `VITE_*`（`VITE_*` 会被打进前端产物）、git。
4. **`users` 表迁移（新增列，不改既有列）**：`openid`（string 64, nullable, **unique**）、`unionid`（string 64, nullable, index）、`wx_bound_at`（timestamp, nullable）。不加外键、不动 `role/roles/venue`——现有权限体系（`userRoles()` / `requireSuper()`）完全复用，小程序登录只是「换一种方式认人」，不是新的身份源。
5. **`session_key` 不落库、不下发**：只在 `wx-login` 请求生命周期内存在。若将来要做「手机号快速验证」（`getPhoneNumber`），才需要短期缓存 `session_key`（内存/Redis，TTL ≤ 5 分钟），M2 不需要。
6. **错误码映射表**（直接抄官方表，别自创）：

| `errcode` | 小程序侧提示 | 后端动作 |
|---|---|---|
| `-1` | 微信服务繁忙，请重试 | 记日志，回 200 + `{code:1}` |
| `40029` | code 无效，请重试 | 让前端重新 `wx.login`（code 5 分钟且一次性） |
| `40226` | 当前微信账号存在风险，暂时无法登录 | 不改业务，提示走账号密码登录 |
| `45011` | 登录过于频繁，请稍后再试 | 同时检查自家 `throttle` 是否被打满 |

7. **不要**在 `wx-login` 里复用 `throttle:10,1`（`routes/api.php:60`）——静默登录在冷启动即触发，10 次/分钟的额度会被「用户反复切前台」打满；给它独立的 `throttle:20,1`。
8. **不需要 `session_key` 校验登录态**（`/wxa/checksession`）：本项目用 Sanctum token 做会话，`session_key` 与业务鉴权无关。别引入第二套登录态。

#### 2.5.3 与现有 user 的关系（明确边界）

| 问题 | 结论 |
|---|---|
| `openid` 放 `users` 还是新表？ | 放 `users` 加列。1 个员工 = 1 个微信 = 1 行，建新表只会带来 JOIN 与「同一人两个身份」的歧义 |
| 一个微信能绑多个员工账号吗？ | 不能。`openid` unique 约束保证 1:1；解绑走管理员操作（`accounts` 域已有超管端点，`routes/api.php:132-137`） |
| 现有 web 端会受影响吗？ | 不会。`openid` 全 nullable，`/auth/login` 一行不改；`userInfo()` 也不必下发 `openid`（避免把微信标识暴露给 web） |
| 权限如何判定？ | 完全复用 `roles`（`User::$fillable` 已含 `roles`，`User.php:24-36`）。微信登录只解决「你是谁」，不解决「你能干什么」 |

## 3 文件上传（`wx.uploadFile` 差异 + 是否真需适配）

### 3.1 现状：只有 3 处 `$r->file()`

| 端点 | 用途 | 约束 | 锚点 |
|---|---|---|---|
| `POST /api/backup/restore` | 上传 zip 恢复整库 | `mimes:zip`、`max:512000`（500MB） | `BackupController.php:211-216` |
| `POST /api/payroll/profiles/import-master` | 人员主档 xlsx 导入（含 `dryRun`） | `max:10240`（10MB），仅 `.xlsx` | `PayrollController.php:355-372` |
| `POST /api/payroll/performance/{preview,commit}` | 业绩表 xlsx 上传解析 | `max:10240`，仅 `.xlsx`，另有 `previewSha256` 防换文件 | `PayrollController.php:734-770`、`1007-1014` |

### 3.2 `wx.uploadFile` 与 web 的差异（一手文档核实）

| 差异点 | 官方原文 / 事实 | 影响 |
|---|---|---|
| 请求本质 | 「客户端发起一个 **HTTPS POST** 请求，其中 `content-type` 为 **`multipart/form-data`**」 | 与 axios `FormData` 等价，Laravel `$r->file()` 无感 |
| `header` 限制 | 「HTTP 请求 Header，**Header 中不能设置 Referer**」 | Bearer 可设 |
| **返回体类型** | `success` 回调 `res.data` 类型是 **`string`**（不是 object） | **必须 `JSON.parse(res.data)`**；axios 会自动解析，小程序**不会**。直接当对象用 → 拿到 `undefined` |
| 只有一条文件 | 单次调用一个 `filePath` + 一个 `name` | 多文件要循环调用（本项目无多文件端点） |
| 额外字段 | `formData`（Object） | `dryRun` 这类参数放这里；注意 `formData` 值会被转成字符串，`false` 会变成 `"false"`，后端 `$r->boolean('dryRun')` 能正确解析（Laravel `boolean()` 认 `"false"`），但**若走 `$r->validate(['dryRun'=>'boolean'])` 且传空字符串会校验失败**——建议小程序侧只在 `true` 时传 |
| 超时 | 默认 `60000`ms（`networkTimeout.uploadFile`），可用 `timeout` 参数覆盖（2.10.0起） | 500MB 备份上传必然超 60s |
| 无 SSE/流式 | 不适用 | — |
| 临时文件来源 | `filePath` 是「本地路径」，来自 `wx.chooseMessageFile` / `wx.chooseMedia` 等 | 选文件的能力受**客户端类型**限制（详见 3.3） |

### 3.3 判定：这些端点「能不能适配」≠「该不该适配」

| 端点 | 技术可行性 | 产品判断 | 结论 |
|---|---|---|---|
| `/backup/restore` | 可（`wx.uploadFile` 传 zip；但 500MB 上传在移动网络几乎不可用） | 整库覆写、超管专属、灾难恢复场景，必然坐在电脑前 | **NO-GO（明确排除）** |
| `/payroll/profiles/import-master` | 可（xlsx，10MB 合理） | 薪酬主档导入，超管 + 财务，一年几次 | **NO-GO（排除，保留 web）** |
| `/payroll/performance/*` | 可（xlsx，10MB） | 同上，且 `previewSha256` 二次上传流程在手机上极易出错 | **NO-GO（排除）** |

**支持这个判断的额外证据**：三个端点全部 `requireSuper()`（`BackupController.php` restore 首行、`PayrollController.php:356`、`:734`、`:746`），即只有馆主/超管本人可用。一麦的超管操作天然是桌面场景（备份路径、xlsx 源文件都在电脑上）。把这三个搬进小程序，收益近乎零，风险是「手机上误点恢复 = 整库覆写」。

**若将来某天必须做**（例如财务只在手机上收到工资表），最小代价路径是：`wx.chooseMessageFile`（从微信聊天里选 xlsx，这是员工真实的文件来源）→ `wx.uploadFile` → `JSON.parse(res.data)` → 复用同一端点，**后端 0 改动**。这条路径要写进「未来可选」，不进 M2。

**顺带一条已有的护栏**：请求体超 `post_max_size` 时后端会返回 `{code:1, message:'...'}` + **413**（`VisionAttachments::renderPostTooLarge`，`app/Support/VisionAttachments.php:226-233`）。小程序侧必须按 `statusCode===413` 单独提示，否则用户看到的是「上传失败」而不知道是文件太大。

## 4 文件下载（`wx.downloadFile` + `wx.openDocument` 能力边界）

### 4.1 现状：真正的下载端点只有 2 个（基线卡的一处锚点需纠正）

> **纠正 `00-基线事实卡.md` §4**：`SystemController.php:123,148` **不是下载端点**。`123` 行是 `changelog()` 里 `if (is_file($f))`，`148` 行是 `update()` 里 `if (! is_file($script))`。`/system/*` 六个端点全是 JSON，无文件流。

| 端点 | 产物 | 实现 | 锚点 |
|---|---|---|---|
| `GET /api/backup/download?scope=local\|remote&name=` | 备份 **zip** | `response()->download(...)` / `->deleteFileAfterSend(true)` | `BackupController.php:168-182`（`177`、`181`） |
| `GET /api/sync-artifacts/{artifact}/download` | 同步产物（xlsx / 压缩 json，`.gz` 走 `streamDownload`） | `streamDownload` + `Content-Length`，或 `response()->download` + `Content-Type: $artifact->mime` | `SyncJobController.php:73-106`（`86`、`104`） |

两者都是 `requireSuper()`（`BackupController.php:169`、`SyncJobController.php:75`）。

### 4.2 能力边界（一手文档核实）

| 能力 | 官方结论 | 判定 |
|---|---|---|
| `wx.downloadFile` | 「下载文件资源到本地。客户端直接发起一个 **HTTPS GET** 请求，返回文件的本地临时路径，**单次下载允许的最大文件为 200MB**」；「请在服务端响应的 header 中指定合理的 **`Content-Type`**」；`header` 同样「不能设置 Referer」；`timeout` 默认 60000 | 可用；**200MB 硬上限** |
| `wx.openDocument` 支持的 fileType | `doc` / `docx` / `xls` / **`xlsx`** / `ppt` / `pptx` / `pdf`（`fileType` 1.4.0 起，`showMenu` 2.11.0 起） | **xlsx 能开** |
| zip 能开吗 | **`fileType` 合法值枚举里没有 zip**，官方未提供任何「解压/浏览压缩包」的客户端能力 | **zip 不能开** |
| 打开后的菜单 | 「微信客户端 `7.0.12` 版本前默认显示右上角菜单按钮，之后的版本默认不显示，需主动传入 `showMenu`」 | 要「转发给别人」必须显式 `showMenu:true` |
| 下载后转发 | 若需发到微信会话，走 `wx.shareFileMessage`（另一 API，非本文范围） | 备选，不作为默认路径 |

### 4.3 判定

| 场景 | 小程序可行性 | 结论 |
|---|---|---|
| **备份下载（zip）** | `downloadFile` 能下（≤200MB），但 `openDocument` 打不开 zip；且备份体积可能超 200MB；且超管桌面场景 | **NO-GO，M2 明确排除**。若硬要做，唯一体验是「下载后 `wx.shareFileMessage` 发给自己」，价值低于成本 |
| **同步产物下载（xlsx）** | `downloadFile` → `openDocument({fileType:'xlsx', showMenu:true})` 可用 | **可做，但优先级低**（超管 + 历史快照场景）。工作量约 0.5 人日 |
| 普通图片/PDF 附件 | 直接 `<image>` / `openDocument` | 不在本次范围 |

**一条容易被忽略的坑**：`downloadFile` 命中 4xx（例如 401、404「历史导入表格不存在」）时同样**进 `success`**（官方：无论 `statusCode` 是多少都进 success，`framework/ability/network.html`），且此时 `tempFilePath` 指向的是一个**装着错误 JSON 的文件**。若不做 `statusCode` 判定就把 `tempFilePath` 丢给 `openDocument`，用户会看到「文档损坏」，而真实原因是 token 过期。

### 5.2 响应契约：不止三形态，实际有 **7 种**

| ① | `{code:0, data}` | `ok()`，`app/Support/helpers.php:31-34`（全站主形态） | 200 | 返回 `data` ✅ |
| ② | `{code:1, message}` | 例：`AiController.php:130,154,192`、`bootstrap` 无 | 200 **或** 422/500（同一形态两种状态码） | 抛错 ✅ |
| ③ | `{ok:true}` / `{ok:true, ...}` | `MarketingFavoriteController.php:97`、`KyController.php:27`、`AccountController.php:205,247`、`MarketingController.php:61`、`ProfileController.php:117`、`ShareController.php:346,492,577,881`、`KyCourseRecordService.php:127` | 200 | 返回 `undefined` ⚠️（payload 在顶层，`data` 不存在） |
| ④ | `{errno:404, emsg}` | `PublicShareController.php:26,62,116`、`ShareController.php:440,481,506` | **404 / 503 / 422** | 抛错 ✅（唯一自带语义的状态） |
| ⑤ | `{message, errors}` | Laravel `ValidationException` 默认渲染（如 `AuthController.php:24-26`） | 422 | 返回 `undefined` ❌ **静默判成功** |
| ⑥ | `{message:'Unauthenticated.'}` | `bootstrap/app.php:37-41` | 401 | 返回 `undefined` ❌ **静默判成功** |
| ⑦ | `{message:'账号已停用'}` | `EnsureUserIsEnabled.php:24`（`abort_if`） | 403 | 返回 `undefined` ❌ **静默判成功** |

另有两处**形状例外**必须记住：
- `logout` 返回 **`{code:0}`（无 `data` 键）** —— `AuthController.php:112`。
- `PayrollController.php:775` 的 `{'message':..., 'code':'PREVIEW_STALE'}`：**`code` 是字符串**。任何 `if (!body.code)` 式判断都会把它当成功。

### 5.3 `unwrap` 契约（必须原样复刻，且要更严）

web 端基准逻辑（`admin-web/src/api/backend.ts:58-72`）依次做三件事，**顺序不能改**：

1. `body.code !== undefined && body.code !== 0` → 抛 `message`
2. `body.ok === false` → 抛 `message || emsg`
3. `body.errno !== undefined && String(body.errno) !== '0'` → 抛 `emsg || message`
4. 否则 `return body.data`

小程序侧复刻版（**契约基准**，仅文档，不落地）：

```ts
// docs-only contract sketch —— 与 admin-web/src/api/backend.ts:58-72 等价 + 增补 statusCode 闸门
function unwrap<T>(statusCode: number, body: any): T {
  // ① 先按 HTTP 状态码定性（web 由 axios 天然完成，小程序必须手写）
  if (statusCode === 401) throw new AuthExpiredError(body?.message || '登录已过期')
  if (statusCode === 403) throw new Error(body?.message || '无权限执行此操作')
  if (statusCode === 413) throw new Error('文件过大，请压缩后重试')
  if (statusCode === 429) throw new Error('操作过于频繁，请稍后重试')
  if (statusCode >= 500) throw new Error(body?.message || '服务异常，请稍后重试')

  // ② 再走与 web 完全一致的三形态判定（顺序不可调换）
  if (body?.code !== undefined && body.code !== 0) throw new Error(body.message || '请求失败')
  if (body?.ok === false) throw new Error(body.message || body.emsg || '请求失败')
  if (body?.errno !== undefined && String(body.errno) !== '0') throw new Error(body.emsg || body.message || '请求失败')

  // ③ 4xx 兜底：任何未带 code/ok/errno 的 4xx 都必须抛，不能落到 return
  if (statusCode >= 400) throw new Error(body?.message || `请求失败（HTTP ${statusCode}）`)

  return body?.data as T
}
```

**为什么第 ③ 步不可省**：`⑤⑥⑦` 三种形态都是「有 message、无 code/ok/errno」，前两步全部放行。少了第 ③ 步就是「密码错→显示登录成功」「token 过期→页面全空但不报错」。

### 5.4 「静默判成功」陷阱矩阵（这是真实陷阱，不是理论风险）

前提铁律（官方原文，`framework/ability/network.html`，2026-11-03）：
> **「只要成功接收到服务器返回，无论 `statusCode` 是多少，都会进入 `success` 回调。请开发者根据业务逻辑对返回值进行判断。」**

| 触发场景 | 后端实际响应（文件:行） | web 端（axios） | 小程序端**照搬 unwrap** | 用户看到 |
|---|---|---|---|---|
| 密码错误 | 422 `{message:'账号或密码错误', errors:{userName:[...]}}`（`AuthController.php:24-26`） | 进 error 分支 → 登录页显示「账号或密码错误」 | 三形态全放行 → 返回 `undefined` | **「登录成功」，但没 token，进去就白屏** |
| token 过期（>14 天） | 401 `{message:'Unauthenticated.'}`（`bootstrap/app.php:37-41` + `sanctum/Guard.php:128`） | 拦截器 `status===401` → `expireSession()` → 踢回登录页 | `success` 里 `statusCode=401`，三形态放行 → `undefined`；**登出逻辑永不触发** | 页面所有列表空白，刷新无效，用户以为「数据没了」 |
| 账号被停用 | 403 `{message:'账号已停用'}`（`EnsureUserIsEnabled.php:24`） | `status===403` → 归一化提示「无权限执行此操作」（`backend.ts:94-97`） | 同上 → `undefined` | 空白页面，无任何提示 |
| 分享链接失效 | 404 `{errno:404, emsg:'分享不存在或已停用'}`（`PublicShareController.php:26`） | 抛 `emsg` | 抛 `emsg` ✅（形态 ④ 自带语义，唯一安全的一种） | 正常报错 |
| 路由不存在 | 404 `{message:...}`（Laravel 默认） | error 分支 | 放行 → `undefined` | 空白 |
| 限流 | 429 `{message:'Too Many Requests'}`（全局 `throttle:120,1`，`bootstrap/app.php:33`） | error 分支 | 放行 → `undefined` | 点击无反应 |
| `{ok:true}` 类写入成功 | 200 `{ok:true}`（7 处，见 5.2 ③） | 返回 `undefined`，调用方一般不用返回值，所以无感 | 返同 `undefined` ✅ 但**若调用方读 `data.xxx` 会炸** | 可能「成功但没拿到新 id」 |

**结论**：形态 ③ 在 web 上「能用」是**巧合**（调用方恰好不读返回值），小程序侧一旦在形态 ③ 端点上读 `data`，就会稳定复现空值。复刻时必须在 `@/api` 层就地标注每个端点的返回形态，不能靠猜。

### 5.5 复刻范围：哪些必须一起搬

| 必须复刻 | web 锚点 | 不复刻的后果 |
|---|---|---|
| `unwrap` 三形态判定（顺序一致） | `backend.ts:58-72` | 见 5.4 |
| `statusCode` 闸门 | web 由 axios 提供 | 401/403/422/429/500 全部静默 |
| 401 单例去重 + `expireSession` 闩锁 | `backend.ts:15-28` | 并发 10 个请求全 401 → 10 次登出/10 次弹窗 |
| 「token 已换过则忽略旧 401」 | `backend.ts:84-93` | 换账号瞬间被旧请求踢下线 |
| 403 消息归一化 | `backend.ts:94-97` | 用户看到笼统「加载失败」 |
| 20s 超时基线与 AI 端点特例 | `backend.ts:52`（`timeout:20000`）、`apiPost` 第三参（`backend.ts:110-117`，`timeout?: number` 在 `113`） | AI/上传类端点被 20s 砍断；小程序默认 60s 反而更宽松，但**必须显式** |
| 基址来源优先级 | `backend.ts:49-53`（`window.__YIMAI_API_BASE__` > `VITE_API_BASE` > `/api`） | 小程序无 `window`，必须改为「写死合法域名 + 环境切换」 |

注意最后一条的**语义变化**：web 的 `/api` 是同域反代（`admin-web/.env.production` 的 `VITE_API_BASE=/api`），小程序**没有同域概念**，必须写完整 `https://<已备案域名>`，且该域名必须在白名单里（§6）。这不是「照抄一个常量」，是「多一个运维依赖」。

## 6 CORS 与域名：代码层不用改，运维层必须配

### 6.1 CORS 现状：不是「缺失」，是「框架兜底生效」

| 事实 | 证据 |
|---|---|
| `backend/config/cors.php` **不存在** | `【源码】` `ls backend/config/` 只有 app/auth/cache/database/filesystems/logging/mail/queue/sanctum/services/session |
| Laravel 12 默认全局中间件**包含** `HandleCors` | `【框架源码】` `vendor/laravel/framework/src/Illuminate/Foundation/Configuration/Middleware.php:453-458`（`getGlobalMiddleware()` 数组里第 5 项） |
| 应用没有移除/替换它 | `【源码】` `backend/bootstrap/app.php:27-35` 只做 `redirectGuestsTo` / `throttleApi` / `api(append: [...])`，无 `->global()` 覆盖 |
| 缺 `config/cors.php` 时用框架内置默认值 | `【框架源码】` `vendor/laravel/framework/src/Illuminate/Foundation/Bootstrap/LoadConfiguration.php:204-213`（`getBaseConfiguration()` 扫 `framework/config/*.php` 作为基底，应用 config 覆盖之） |
| 框架默认值 = 全放开 | `【框架源码】` `vendor/laravel/framework/config/cors.php`：`paths: ['api/*','sanctum/csrf-cookie']`、`allowed_methods:['*']`、`allowed_origins:['*']`、`allowed_headers:['*']`、`supports_credentials:false` |
| 版本 | `【源码】` `backend/composer.lock:1063` → `laravel/framework v12.68.0` |

**判定**：`/api/*` 上的跨域请求当前是「任意 Origin + 任意头 + 任意方法，不带凭证」。web 端是**同域反代**（`VITE_API_BASE=/api`），根本不发跨域请求，所以这套默认值一直没被检验过。

**要不要补 `config/cors.php`？** M2 **不需要**——小程序不发浏览器 CORS 请求。但建议补一份**收紧版**（`allowed_origins` 只留自有域），理由是当前 `['*']` 意味着任何网页都能从浏览器直连 API 并读响应；虽然 Bearer token 挡住了未授权访问，但这是免费的纵深防御。工作量 0.2 人日，不阻塞 M2。

### 6.2 小程序为什么不受 CORS 约束

`wx.request` 由**客户端原生**发出（官方文档把 Referer 固定成 `https://servicewechat.com/{appid}/{version}/page-frame.html`，见 `framework/ability/network.html`），不是浏览器 XHR，没有同源策略、没有 `Origin`、没有预检。官方文档对 `wx.request` 的限制只列了：域名白名单、HTTPS/证书、并发数、Referer 不可设——**通篇未提 CORS**（同上 URL，2026-11-03）。

**但 web-view 例外**：若用 `web-view` 内嵌现有 H5 分享页（`/s/:code` 等），里面的 `fetch/axios` 就是**真浏览器环境**，此时 ① 受 CORS 约束（`allowed_origins:['*']` 恰好能过）② 受**业务域名**白名单约束（另一套配置，需上传校验文件）——`web-view` 官方原文：「可打开关联的公众号的文章，其它网页需登录小程序管理后台配置**业务域名**」（`/component/web-view.md`，2026-11-03）。这两套域名**不是同一个东西**，运维别配错。

### 6.3 服务器域名白名单：运维前置清单（这是唯一真正会卡住上线的东西）

官方原文（`framework/ability/network.html`，2026-11-03）逐条落地到一麦：

| 官方要求 | 一麦的现状/动作 | 状态 |
|---|---|---|
| 「小程序**只可以跟指定的域名**进行网络通信」，含 `wx.request` / `uploadFile` / `downloadFile` / `connectSocket` | 必须在「小程序后台-开发-开发设置-服务器域名」逐条加：**request 合法域名**（API 基址）、**uploadFile 合法域名**（若做上传）、**downloadFile 合法域名**（若做下载） | ❗**未知**（`00` §6.4 记「无服务器域名白名单相关运维记录」） |
| 「域名只支持 `https`」 | 现有生产为同域反代（`VITE_API_BASE=/api`），**是否为独立备案域名 + 有效证书需运维核实** | ❗待核 |
| 「域名**不能使用 IP 地址**或 localhost」 | 不能直接用 `115.29.231.55` / `47.115.231.243`；生产 API 必须挂在域名后 | ❗待核（画像里两台生产机都是裸 IP + 宝塔端口） |
| 「域名必须经过 **ICP 备案**」 | `shunan.fun` / `nbyimai.com` / `nbyimai.cn` 的备案状态需核实（海外注册商/Cloudflare 代理不影响备案要求，但会影响国内可访问性） | ❗待核 |
| 「**不支持配置父域名**，使用子域名」 | 若 API 在 `api.example.com`，白名单必须写 `api.example.com`，不能写 `example.com` | 待配置 |
| 「可以配置端口…配置后**只能**向该端口请求；不配端口则 URL 里连 `:443` 都不能有」 | 若沿用宝塔的非标端口（画像中见过 `:19319` / `:36119` 是面板端口，API 端口需另确认），白名单端口必须与 URL **逐字符一致** | ❗**高危**：这是最常见的「开发能通、真机 404」原因 |
| 「HTTPS 证书必须有效、域名一致、在有效期、信任链完整；iOS 不支持自签名；TLS ≥ 1.2」 | 需用 `openssl s_client -connect <域名>:443` 验证（官方推荐命令） | 待核 |
| 「`api.weixin.qq.com` 不能被配置为服务器域名」 | 决定了 `code2session` **必须**后端代理（§2.5） | ✅已定 |
| 并发上限 10 | 小程序首屏若并发拉 8+ 接口需排队（`today` 8 条 + 通知 + 用户信息） | 设计约束 |
| 「进入后台运行后，如果 **5s** 内网络请求没有结束，会回调错误 `fail interrupted`」 | AI 生成、上传、下载全部会撞；必须设计「回前台重试」 | **设计约束（P0）** |
| 预解析域名最多 5 个 | 可选优化 | 可选 |

**给运维的一句话**：代码层一行不用改，但「域名 + 备案 + 证书 + 端口精确匹配 + 白名单三条（request/upload/download）」不全部就绪，小程序**一个请求都发不出去**，且报错是 `url not in domain list`，与业务代码无关。**这是上线前置的硬闸门，建议单独立项。**

## 7 公开发布接口：`/api/public/*` 能否直接给小程序用

### 7.1 现状

| 事实 | 锚点 |
|---|---|
| 3 条免登录端点：`/public/training/{code}`、`/public/post-class/{code}`、`/public/sales/{token}` | `routes/api.php:256-260` |
| 组级限流 `throttle:60,1` | `routes/api.php:256` |
| 全局 api 组限流 `throttle:120,1`（**同样作用于 public**） | `bootstrap/app.php:33` |
| 成功形态 `{code:0,data}`（`ok()`） | `PublicShareController.php:40`、`:80`、`:126` |
| 失败形态 `{errno:404, emsg}` + **HTTP 404** | `PublicShareController.php:26,62,116` |
| 业务上 fail-closed：`share.enabled` 显式真值比较、`status==='已确认'`、`red_flag` 直接 404 | `PublicShareController.php:22-27`、`:61-64`、`:113-118` |
| 每次访问做行锁 +1 views（写库） | `PublicShareController.php:29-35` 等（`DB::transaction` + `lockForUpdate`） |
| 销售分享下发走**逐层白名单**清洗 | `PublicShareController.php:100-128` + `ShareController::sanitizeSalesPayload()` |

### 7.2 判定：可直接复用，但限流要单开桶

| 问题 | 结论 |
|---|---|
| 能否直接给小程序调？ | **能**。免登录 + 形态稳定（成功 ①/失败 ④，是 7 种形态里最干净的组合）+ 有 `isTrustedToken`/`isEnabled` 双重 fail-closed。小程序里做「学员看自己的训练方向」页，比 `web-view` 套 H5 体验更好，也避开业务域名配置 |
| 双桶会不会互相挤？ | 会。两个 `throttle` 都按 **未登录 → IP** 计数（Laravel `ThrottleRequests` 的 key 规则）。effective = 60/min/IP/路由组；全局 120/min 是另一个桶，不叠加但不解除。**同一健身房 WiFi（NAT 单出口）下几十个学员同看分享页，60/min 会打满** |
| 是否需要为小程序单开限流 | **建议开**，但不必进 M2 第一版。做法：在 `AppServiceProvider`/`bootstrap` 注册命名限流器 `RateLimiter::for('miniapp-public', fn($r) => Limit::perMinute(120)->by($r->ip()))`，再把 public 组改成 `throttle:miniapp-public`。或者更精确：按 `code/token` 而非 IP 计数（分享链接天然带唯一 token，按 token+IP 组合更贴合真实用量）。工作量 0.5 人日 |
| 写库放大风险 | 每次 GET 都 `lockForUpdate` 写 `views`。小程序若做「下拉刷新」会加速写库；且小程序无法可靠区分「同一人多次打开」。建议小程序侧不做自动刷新，且后端可考虑 `views` 改为每 N 分钟聚合（非 M2 必需，记录为观察点） |
| 分享开关状态一致性 | `ShareController::current`（`routes/api.php:217`）是「本人当前分享的权威状态」，小程序内如果展示「我的分享链接」，必须读这个端点，不能本地拼 |
