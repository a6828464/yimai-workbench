## 4 自检（判断配置是否真的通了）

```bash
curl -s -X POST https://oa.nbyimai.com/api/auth/wx-login \
  -H 'Content-Type: application/json' -d '{"code":"probe"}'
```

| 返回 | 含义 |
|---|---|
| 422「微信登录凭证已失效，请重试」 | ✅ **正确**：appid/secret 都对，只是 code 是假的（微信 40029） |
| 422「微信登录未开通，请使用账号密码登录」 | secret 或 appid 为空 → 没写进 `.env` 或没 `config:cache` |
| 422「微信登录配置有误，请联系管理员检查小程序密钥」 | 微信回 40125 → secret 值错（复制不全/已重置） |
| 422「微信登录配置有误…检查小程序 AppID」 | 微信回 41002 → appid 与 secret 不配对（换过小程序？） |
| 429 Too Many Requests | 限流 `throttle:6,1`，等 1 分钟再试 |

2026-11-04 03:46 实测：前两条探测都返回「凭证已失效」，第三条撞上 429（`x-ratelimit-limit: 6`）——**说明配置正确，链路已通到微信**。

## 5 轮换与应急

1. mp 后台重置密钥 → 新旧同时失效（微信不保留旧值）
2. 生产 `.env` 改值 → `php artisan config:cache`
3. 重新自检（§4 第一行应回到「凭证已失效」）
4. 密钥泄露时的处置：重置即可，**不需要改 appid**、不需要重新上传代码（secret 不在产物里）

备份文件（服务器）：`.env.bak-wxlogin-0342`（写 appid 前）、`.env.bak-secret-0345`（写 secret 前）。

## 7 勘误：`WECHAT_AUTO_BIND_BY_PHONE` 是空写

`grep -rn "WECHAT_AUTO_BIND_BY_PHONE|auto_bind" backend/app backend/config` → **0 命中**（2026-11-04 03:47 核实）。
手册 `07` §1 与本文初稿都把它列成配置项，实际代码从不读取。真实行为由 `AuthController::wxLogin` 写死：
openid 命中 `users.wx_openid` 才放行，否则 403。改成 `true` 不会有任何变化。

要用到它得先实现「按手机号自动绑」：`code2session` 不返回手机号，必须加 `getPhoneNumber` 组件 + 解密，
这是另一项能力，不在本轮范围。
