## 1 契约单一真源（必须覆盖项 ①）

### O-01 · 契约没有单一真源，字段理解靠人肉对齐

| 字段 | 内容 |

### O-03 · `unwrap` 之外还有一层「静默成功」风险：`code !== 0` 之外的成功形态没有被穷举

| 字段 | 内容 |
|---|---|
| **问题** | `unwrap()` 的判定是「`code` 有值且非 0 → 抛」「`ok === false` → 抛」「`errno` 非 0 → 抛」，其余一律 `return body.data`。若后端某端点返回 `200 + {message:'失败'}`（无 `code`）或直接返回裸数组，前端会**当作成功且 data 为 undefined**。 |
| **证据【实】** | `admin-web/src/api/backend.ts:66-71`：三个 `if` 之后无条件 `return body?.data as T`。类型断言 `as T` 使 TS 无法发现。当前后端 `ok()`（`helpers.php:31-34`）恒带 `code:0`，**主通路暂时安全**；但 `keepyoga.ts` 代理第三方响应形态不受此保证（`:40-45` 已单独再做一次 `errno` 判断，说明作者也知道外层 `unwrap` 不够）。 |
| **动作** | 在 core 的 `unwrap()` 里改为**白名单**：只有 `code === 0` 或（无 `code` 且无 `ok` 且无 `errno`）且响应 `content-type` 为 JSON 时才放行；其余抛 `ApiError('响应格式不符合契约', { raw: body })`。同时给 `unwrap` 加可选 `{ endpoint }` 参数，错误信息带上端点名，便于定位。 |
| **收益** | 把「静默 undefined」变成「显式报错」。`ff6f03f` 那两处整页白屏的触发条件之一就是「数据是 undefined 但代码当成对象用」；这一条是同类问题的**上游闸门**。 |

### O-16 · web-view 允许清单 / 禁止清单

**判定规则（三条，按顺序问）**：
1. **是否需要小程序的登录态？** 需要 → 禁止 web-view（小程序 web-view 是独立 web 容器，**不共享小程序的会话**，也不会自动带上 Bearer token）→ 必须原生。

## 8 方法论：如何判断「这段代码能不能进小程序」（可执行校验，不靠人眼）

> 这条是 captain 那条被撤回的结论换来的，**必须固化下来**，否则下次还会有人用字面量 grep 得出「只有 3 个文件 49 处」这种结论（真实情况是「0 处字面量 → 全量模块依赖」）。

### 8.1 为什么字面量 grep 会系统性低估

`api/ai.ts` 字面量浏览器 API 计数 = **0**，但它的模块图里 100% 依赖 `localStorage` 与 `window.location`（路径见 §0.2）。原因有两个：

1. **传递依赖**：`import { useUserStore } from '@/store/modules/user'` 一行就把整条 `user.ts:37 → @/router → createWebHashHistory` 拉进来。
2. **模块求值期 vs 调用期**：`createRouter(...)` 在 **import 时**就跑；`createToken` 类的东西在调用时才跑。前者是**致命**的（import 即崩），后者可以用适配层延后。

### 8.2 三道校验（按成本从低到高，建议全部进 CI）

| # | 校验 | 命令（可直接跑） | 能抓到什么 | 抓不到什么 |
|---|---|---|---|---|
| 1 | **字面量扫描**（5 秒） | `grep -rnE "localStorage|sessionStorage|window\.|document\.|navigator\.|XMLHttpRequest|URL\.createObjectURL|new FormData|FileReader|new Image\(\)" src --include=*.ts --include=*.vue \| wc -l` | 直接依赖 | **传递依赖（本次踩的坑）** |
| 2 | **模块图扫描**（30 秒，**关键**） | 用 `vite build --mode miniapp-check` 生成 `dist/metafile.json`（配 `rollup-plugin-visualizer` 已在 devDeps 里），或直接 `node -e` 走 `esbuild --bundle --metafile`，然后**对每个 entry 求「可达模块集合」，检查是否包含黑名单模块**（`vue-router`、`pinia-plugin-persistedstate`、任何命中 `src/router/`、`src/store/index.ts` 的模块） | **传递依赖**，含 import 即执行的 | 运行时才用到的（如方法体内的 `localStorage`） |
| 3 | **产物字面量扫描**（10 秒） | `grep -l "localStorage" dist/assets/*.js` | 最终是否真的进了包 | 同上 |

**本次的教训要写成一条 CI 规则**：

```
# 伪代码：packages 边界检查（可放进 scripts/check-miniapp-safe.ts，复用现有 tsx 运行）
禁止 shared/ 与 api/ 下的任何模块，在「可达模块集合」中出现：
  - src/router/**
  - src/store/index.ts
  - 任何含 `localStorage` 字面量的模块
违规即 fail，并打印「违规模块 → 引入路径」的反向链。
```

> 现成的 `scripts/check-pii-storage-keys.ts` 已经证明「用 tsx 跑脚本做门禁」这条路在这个项目里是通的（`package.json` `check:pii-storage-keys`），**新校验直接照着它的形状写即可**。

### 8.3 一条更便宜的经验规则

> **凡 import 了 `@/store/` 或 `@/router` 的文件，默认视为「不可进小程序」，除非逐行审过。**
> 本项目的 `store/modules/user.ts:37` 一处 `import { router }` 就把整个 router 拉进了所有 api 文件的依赖图——这是**单点污染源**，优先摘掉它，收益最大。

## 11 一句话结论

> 一麦在「搬小程序」这件事上最值钱的资产不是后端 136 条路由，而是**已经验证过的 25 个移动端卡片页信息架构**（可直接复用为小程序页面设计规格）；最大的风险不在工作量，而在**平台依赖比看起来深一层**——`api/ai.ts` 的字面量浏览器 API 是 0，模块图依赖是 100%。
>
> 因此优化顺序应该是：**先花 2.9 人日把「网络 + 存储 + web-view/依赖边界」三块地基换成平台无关形态**（批次 B），**并行花 1.9 人日做零风险的删依赖与错误上报**（批次 A），最后在开发期用真实端点清单反向约束契约层（批次 C，3.8–5.8 人日）。这三步做完，「多端并存 = 两套维护」的概率会显著低于「多端并存 = 一套 core + 三个薄适配」。
