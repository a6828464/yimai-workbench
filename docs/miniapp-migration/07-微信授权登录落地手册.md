## 0 这条链路长什么样

```
小程序 wx.login()
   → code
   → POST /api/auth/wx-login {code}
   → 服务端 code2session（appid + secret 只在服务端）
   → openid
   → 查 users.wx_openid
        ├─ 命中 → 检查 status → 签 Sanctum Token → 登录成功
        └─ 未命中 → 403「该微信尚未绑定员工账号」 ← 这里必须由管理员处理
```

**设计上刻意不做的事**：不自动建号。openid 是「这个微信」，不是「这个员工」；让未绑定的微信自动获得账号，等于把员工系统对任何扫码的人开放。

## 1 服务器环境变量（后端）

在 `backend/.env` 追加三行，然后 `php artisan config:clear`：

```bash
WECHAT_MINI_APPID=wx3a5379d124e2499c          # 与 miniapp/src/manifest.json 的 mp-weixin.appid 必须一致
WECHAT_MINI_SECRET=<小程序后台「开发管理 → 开发设置 → AppSecret」>
WECHAT_AUTO_BIND_BY_PHONE=false               # ⚠ 占位键：代码零引用，改成 true 也不生效（见 10 §7）
```

- `AppSecret` 只在服务端。**任何情况下不要**写进 `miniapp/.env*` —— 那是会被打进产物的。
- 改完必须清配置缓存，否则读到的是旧值：

```bash
cd backend && php artisan config:clear && php artisan config:cache
```

- 自检（不依赖小程序）：

```bash
curl -s -X POST https://oa.nbyimai.com/api/auth/wx-login \
  -H 'Content-Type: application/json' -d '{"code":"invalid-probe"}'
# 期望：422 {"code":1,"message":"微信登录凭证已失效，请重试"}
# 若返回「微信登录未开通，请使用账号密码登录」= 环境变量没生效，回上一步
```

## 2 数据库迁移

```bash
cd backend && php artisan migrate --force
```

新增三列 `wx_openid` / `wx_unionid` / `wx_bound_at` + `wx_openid` 唯一索引。
**唯一索引是关键**：靠应用层「先查再写」在并发下会插出两条绑定，届时同一个微信会随请求落到不同账号。

## 3 给员工绑定微信（管理员操作）

绑定入口在「人员管理」，走三个接口（均要求 `R_SUPER`）：

| 动作 | 请求 |
|---|---|
| 查状态 | `GET /api/accounts/{username}/wx-binding` → `{bound, boundAt, hasUnionid}` |
| 绑定 | `PUT /api/accounts/{username}/wx-binding` body `{"openid":"..."}` |
| 解绑 | `DELETE /api/accounts/{username}/wx-binding` |

**怎么拿到员工的 openid**：openid 不能靠员工自己报（他也看不到）。两条路：

- **推荐**：让员工先用**账号密码**在小程序里登录。此时前端能拿到自己的 openid ——
  在「我的」页加一行「微信绑定」显示当前 openid（M2 待做，见 §5）。
- **临时**：在小程序里打开 vConsole，看 `/auth/wx-login` 的 403 响应体；
  或直接看后端日志 `storage/logs/laravel.log` 里 `[wx-login]` 那一行的上下文。

> ⚠️ `{username}` 含中文时 URL 必须 `rawurlencode`，否则路由层直接回 400（不是 404）。

## 4 为什么默认不自动绑定

微信 `code2session` **不返回手机号**（要手机号得走 `getPhoneNumber` 组件并额外解密，属另一项能力）。因此「openid → 哪个员工」没有可靠自动映射：

- 按昵称/头像猜 → 同名员工直接串号；
- 按 unionid 猜 → 只在同开放平台绑定时才有，且仍不指向员工；
- 自动建号 → 见 §0。

所以绑定是**人为动作**，这也正是它的安全边界。

## 5 前端开关（开关没开，按钮不出现）

`miniapp/.env`（生产）与 `.env.development`（开发）各有一行：

```bash
VITE_WX_LOGIN_ENABLED=false   # 改成 true 并重新构建，登录页才显示「微信授权登录」
```

改完必须重建：

```bash
cd miniapp && npm run build:mp-weixin
```

**已验证的编译行为**（2026-11-04 实测）：`false` 时 `doWxLogin` 被 tree-shaking 完全移除，产物里只剩 `o:false`；`true` 时 `loginWithWechat` 进入 bundle。所以开关不会留下死代码。

> 注意：uni-app **不读 shell 环境变量**，`VITE_WX_LOGIN_ENABLED=true npm run build` 不生效，必须写进 `.env*` 文件。

## 7 已知边界（不要当成 bug 报）

| 现象 | 原因 |
|---|---|
| 未绑定微信登录返回 403 | 设计如此，按 §3 绑定 |
| 解绑后员工仍在登录状态 | 有意：会话是账号级的，解绑不该把人从班上踢下线。要踢人用「停用」 |
| 绑定响应里看不到 openid | 有意脱敏，openid 是可冒用身份键，不回传前端 |
| 同一 openid 绑第二个账号报 422 | 唯一约束的正确行为，先解绑 |
| 中文用户名绑定接口 400 | URL 编码问题，用 `rawurlencode` |
