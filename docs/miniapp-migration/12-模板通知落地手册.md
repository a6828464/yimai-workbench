## 1 这套东西在解决什么

「新客资分到某位老师名下」「会员的会籍顾问/负责人换成某人」这两件事，以前只有站内通知与
今日待办，人不在电脑前就看不到。模板通知把这两件事推到**该负责的那个人的微信**里：

| 触发点 | 代码位置 | 模板键 | 收件人 |
|---|---|---|---|
| 新建客资时填了服务老师 | `LeadController::store` | `leadAssigned` | 该服务老师 |
| 客资的服务老师由空变非空 / 换人 | `LeadController::update` | `leadAssigned` | 新的服务老师 |
| 会员会籍顾问（consultant）变更 | `CustomerController::update` | `leadAssigned`（复用，见 §0） | 新的会籍顾问 |
| 会员负责人（owner）变更 | `CustomerController::update` | `leadAssigned`（复用，见 §0） | 新的负责人 |

会员模板已于 2026-11-04 13:40 独立开通：`memberAssigned.template_id` 非空且 enabled 时，`notifyMemberAssigned()` **自动走 `memberAssigned`**；模板 id 为空时回退 `leadAssigned`（代码内按 config 判断，不需要改代码）。

三条硬纪律（改动前先读，否则一定会踩）：

1. **订阅消息是一次性授权**。用户在 `wx.requestSubscribeMessage` 里点一次「允许」，
   只换到**一次**下发机会，发完即失效；微信侧**没有**任何查询接口。
   「还能发几条」这件事只存在于我们自己的 `wx_subscriptions` 表里。
2. **通知永远不能影响主流程**。触发点一律 `defer(fn () => ...)` + `try/catch` + `Log::warning`，
   微信慢、模板没配、姓名对不上账号，会员/客资照常保存。
3. **未配置不是错误**。三个 `WECHAT_TPL_*` 留空时，接口 `configured=false`，
   页面显示「待管理员配置模板」，发送记 `skipped`，不报错、不重试。

## 2 配置项

### 2.1 `.env`（`backend/.env`，生产在 `/www/wwwroot/yimai/backend/.env`）

```dotenv
# 前置条件：授权登录同款凭据（本仓已有）
WECHAT_MINI_APPID=wx****************
WECHAT_MINI_SECRET=****************

# 三个模板 id，到公众平台「订阅消息 → 我的模板」复制，形如 AbCdEf123...
WECHAT_TPL_LEAD_ASSIGNED=
WECHAT_TPL_MEMBER_ASSIGNED=
WECHAT_TPL_TODO=
```

| 键 | 对应模板键 | 用途 |
|---|---|---|
| `WECHAT_TPL_LEAD_ASSIGNED` | `leadAssigned` | 新客资分配提醒 |
| `WECHAT_TPL_MEMBER_ASSIGNED` | `memberAssigned` | 会员归属变更提醒 |
| `WECHAT_TPL_TODO` | `todoReminder` | 待办提醒（本期只落配置与目录，**未接触发点**） |

改完 `.env` 必须清配置缓存，否则 `config('services.wechat.templates')` 还是旧值：

```bash
cd /www/wwwroot/yimai/backend && php artisan config:cache && php artisan config:clear
```

> 生产如果开了 `config:cache`，`env()` 只在**生成缓存那一刻**求值：只改 `.env` 不重建缓存 = 没生效。

### 2.2 `config/services.php` → `wechat.templates`

键是**我们自己的稳定标识**（小程序、`wx_subscriptions.template_key` 都用它），与微信侧
`template_id` 解耦 —— 重新申请模板只换 env，历史授权账本不丢。

```php
'templates' => [
    'leadAssigned' => [
        'title' => '新客资分配提醒',
        'desc'  => '有新的客资分配到您名下时通知',
        'template_id' => env('WECHAT_TPL_LEAD_ASSIGNED', ''),
        'enabled' => true,            // 临时停用改 false（保留 template_id）
        'page' => '',                 // 留空 = 点通知进小程序首页
        'miniprogram_state' => 'formal', // 调试可改 developer / trial
        'fields' => [
            'thing1' => ['label' => '客户称呼', 'key' => 'customerName'],
            'name2'  => ['label' => '服务老师', 'key' => 'staffName'],
            'time3'  => ['label' => '分配时间', 'key' => 'time'],
            'thing4' => ['label' => '门店',     'key' => 'venue'],
        ],
    ],
    // memberAssigned / todoReminder 同构
],
```

| 配置项 | 含义 |
|---|---|
| `template_id` | 微信侧模板 id。**空 = 该模板未配置**（`enabled=false`、发送 skipped） |
| `enabled` | 临时停用开关（默认 true）。`false` 时保留 `template_id` 但不下发，接口返回 `enabled=false`，页面显示「已停用」 |
| `page` | 点通知后跳转的小程序页面路径。留空走首页；**填错会让整条消息 41030 发不出去**，所以默认不填 |
| `miniprogram_state` | `formal`（正式版）/ `developer`（开发版）/ `trial`（体验版） |
| `fields.<关键词>.label` | 中文名，随接口下发给小程序展示 |
| `fields.<关键词>.key` | 语义值键：`customerName` / `staffName` / `venue` / `role` / `time`。换模板时改**关键词**即可，代码不动 |

## 3 公众号后台申请模板（一次性授权模板）

小程序订阅消息在**微信公众平台**（小程序后台）配置，不是开放平台。

1. 登录 <https://mp.weixin.qq.com> → 选中对应小程序。
2. 左侧「功能 → 订阅消息」。
3. **先确认类目**：公共模板库的可用模板由小程序服务类目决定。本仓类目是「体育/健身」相关，
   若列表里找不到合适模板，先在「设置 → 基本设置 → 服务类目」补齐类目（改类目需要审核）。
4. 点「公共模板库」→ 搜索关键词，按下面推荐选模板：

   | 模板键 | 公共模板库搜索词 | 需要的关键词（顺序可调） |
   |---|---|---|
   | `leadAssigned` | `分配提醒` / `新客户` / `待办提醒` | 客户称呼（thing）、服务老师（name）、时间（time）、门店（thing） |
   | `memberAssigned` | `会员通知` / `客户归属` / `跟进提醒` | 会员称呼（thing）、归属人（name）、身份（phrase）、时间（time） |
   | `todoReminder` | `待办` / `任务提醒` | 待办事项（thing）、截止时间（time）、门店（thing） |

5. 勾选关键词 → 「选用」。**关键词的顺序与编号就是模板参数的键名**：
   第 1 个 thing 是 `thing1`、第 2 个 thing 是 `thing2`，name 从 `name1` 起，time 从 `time2` 起
   —— 平台按「类型 + 序号」自动编号，实号以「我的模板 → 详情」里显示的为准。
6. 「我的模板」→ 复制模板 id（形如 `AbCdEf1234567890abcdef1234567890`）→ 填进对应 `WECHAT_TPL_*`。
7. **把「我的模板 → 详情」里的参数名逐个抄进 `config/services.php` 的 `fields` 键**。
   抄错一个键名不会报配置错误，只会在真发时收到 `47003 模板参数不准确`。

> 一次性订阅 vs 长期订阅：本仓用的是**一次性订阅**（`requestSubscribeMessage` 每次 +1 次机会），
> 长期订阅只对政务/医疗等特定类目开放，健身门店类目拿不到，别去找。

## 4 字段映射表

服务端传给 `send()` 的是**语义键**，由配置里的 `fields.<关键词>.key` 映射到微信参数。
下发前还会按微信的「类型前缀」做一次截断（超长直接 47003，且不告诉你是哪个字段）：

| 类型前缀 | 字符上限 | 本仓用到的字段 |
|---|---|---|
| `thing` | 20 | 客户称呼、门店、待办事项 |
| `name` | 10 | 服务老师、归属人 |
| `phrase` | 5 | 归属身份（会籍顾问/负责人） |
| `time` | 不限（格式 `2019年10月1日 15:01`） | 分配时间、变更时间、截止时间 |
| `date` | 不限（格式 `2019年10月1日`） | 暂未使用 |
| `number` / `character_string` / `letter` | 32 | 暂未使用 |
| `symbol` | 5 | 暂未使用 |

其它口径：

- 值为空 → 自动填 `—`（微信不接受空字符串参数，空参同样报 47003）。
- `\DateTimeInterface` 传进来时自动格式化成上面两种时间格式，调用方不必自己拼。
- 只下发 `fields` 里登记过的参数；多传的语义键被忽略（发送测试时会多传 `role`，不影响 `leadAssigned`）。

当前映射（默认值，按后台模板实号调整）：

| 模板键 | 参数 → 语义键 | 示例值 |
|---|---|---|
| `leadAssigned` | `thing1` → customerName<br>`name2` → staffName<br>`time3` → time<br>`thing4` → venue | 姚女士 / 张三 / 2026年11月4日 21:30 / 绿地店 |
| `memberAssigned` | `thing1` → customerName<br>`name2` → staffName<br>`phrase3` → role<br>`time4` → time | 会员甲 / 李四 / 会籍顾问 / 2026年11月4日 21:30 |
| `todoReminder` | `thing1` → customerName<br>`time2` → time<br>`thing3` → venue | （未接触发点） |

## 5 接口契约（`auth:sanctum`，登录即可，不涉他人数据）

### 5.1 `GET /api/wx/subscriptions`

```json
{
  "code": 0,
  "data": {
    "configured": true,
    "bound": true,
    "templates": [
      {
        "key": "leadAssigned",
        "title": "新客资分配提醒",
        "desc": "有新的客资分配到您名下时通知",
        "enabled": true,
        "templateId": "AbCdEf1234567890abcdef1234567890",
        "accepted": true,
        "remain": 2,
        "lastAcceptedAt": "2026-11-04T21:30:12+08:00",
        "fields": ["thing1", "name2", "time3", "thing4"]
      }
    ],
    "updatedAt": "2026-11-04T21:30:12+08:00"
  }
}
```

字段语义（前端展示口径）：

| 字段 | 含义 | 页面文案建议 |
|---|---|---|
| `configured` | 是否有**任意**模板配了 `template_id` | false → 顶部提示「待管理员配置模板」 |
| `bound` | 本人是否绑了微信（`users.wx_openid` 非空） | false → 「先绑定微信」+ 跳「我的」 |
| `enabled` | 该模板可发：配了 `template_id` 且未被 `enabled=false` 停用 | `templateId` 为空 → 「未配置」；有 id 但 `enabled=false` → 「已停用」 |
| `accepted` | 曾授权过（`total_accepted > 0`） | true 且 remain>0 → 「已授权，剩余 n 次」 |
| `remain` | 现在还能发几条 | 0 且 accepted → 「已用完，点开启提醒重新授权」 |
| `lastAcceptedAt` | 最近一次授权时间 | 「上次授权 …」 |
| `fields` | 模板参数名清单（如 `["thing1","name2","time3","thing4"]`） | 页面不渲染，排障时按这些键名去 `wx_subscription_logs.payload.data` 比对 |

> `configured=false` 时**依然返回 200 + 三个模板**，页面要能正常打开，只是按钮置灰。

### 5.2 `POST /api/wx/subscriptions`

请求：

```json
{ "accepts": ["leadAssigned", "memberAssigned"], "denies": ["todoReminder"] }
```

响应：`ok({ templates: [...], accepted: ["leadAssigned","memberAssigned"] })`

- `accepts` 里每个键：`remain + 1`、`total_accepted + 1`、`last_accepted_at = now()`（upsert）。
- `denies` 与未登记的键：只忽略，不改账本、不报错（授权事件已发生，不该整单失败）。
- 前端只要把 `uni.requestSubscribeMessage()` 返回为 `accept` 的模板 id 对应成键名提交即可。
  重复提交同一个键会再加一次 —— 这是「又点了一次允许」的正确语义，别在前端做去重缓存。

### 5.3 `POST /api/wx/subscriptions/test`

请求：`{ "key": "leadAssigned" }`

成功（微信已受理）：

```json
{ "code": 0, "data": { "sent": true, "message": "已发送，请在微信服务通知中查看" } }
```

业务失败但接口成功（如 43101、或小程序凭据没配）：

```json
{ "code": 0, "data": { "sent": false, "message": "小程序凭据未配置（WECHAT_MINI_APPID / WECHAT_MINI_SECRET 为空）" } }
```

43101（用户拒收）：

```json
{ "code": 0, "data": { "sent": false, "message": "用户未授权或已拒收该模板，请重新点击「开启提醒」" } }
```

未配置 / 未绑定 → **422** + `message` 中文（前端 `miniapp/src/utils/http.ts` 对非 2xx 会直接 toast）：

| 情况 | 状态码 | message |
|---|---|---|
| key 不在目录里 | 422 | `未知的模板：xxx` |
| 该模板 `template_id` 为空 / `enabled=false` | 422 | `模板通知未配置或已停用（leadAssigned），请联系管理员检查 WECHAT_TPL_* 与 config/services.php 的 enabled` |
| 本人没绑微信 | 422 | `尚未绑定微信，请先在「我的」页完成微信绑定` |

接口限流 `throttle:6,1`（每账号每分钟 6 次）—— 每次自测都会真发一条微信消息，不能当免费的连通性探测。

## 6 错误码表（下发链路）

`wx_subscription_logs` 里 `status` 三态：`sent`（微信受理）/ `skipped`（本地不该发）/ `failed`（微信侧报错）。

| errcode | 含义 | 本仓处理 |
|---|---|---|
| 0 | 成功 | `remain--`、写 `last_sent_at`、流水 `sent` |
| 43101 | 用户拒收 / 无有效授权 | **`remain` 归零**、流水 `failed`，页面提示重新授权 |
| 40001 | access_token 无效 | 清 token 缓存、换新 token **自动重试一次** |
| 42001 | access_token 过期 | 同上，重试一次 |
| 40003 | openid 无效 | 流水 `failed`；需要重新绑定微信（`/auth/wx-self-bind`） |
| 40013 | AppID 无效 | 流水 `failed` + error 日志；检查 `WECHAT_MINI_APPID` |
| 40125 | AppSecret 无效 | 流水 `failed` + error 日志；检查 `WECHAT_MINI_SECRET` |
| 40037 | template_id 不正确 | 流水 `failed`；核对 `WECHAT_TPL_*` 与后台模板 |
| 47003 | 模板参数不准确 | 流水 `failed`；看 `payload.data` 里哪个字段超长/格式错，改 `config` 的 `fields` |
| 41030 | page 路径不正确 | 流水 `failed`；把 `page` 清空或改成真实页面 |
| 45009 | 频率超限 | 流水 `failed`；次日或稍后重试 |

`skipped` 的四种原因（写在 `errmsg`，`errcode` 为 null）：

| 原因 | 触发条件 |
|---|---|
| `template_not_configured` | `template_id` 为空 |
| `credentials_missing` | `WECHAT_MINI_APPID` / `WECHAT_MINI_SECRET` 为空 |
| `openid_missing` | 本人没绑微信 |
| `no_remain` | 订阅次数用完（`remain <= 0`） |

## 8 已知边界（交付时的遗留项）

1. **`todoReminder` 只有配置与目录，没有触发点**。待办的指派/临期通知需要先确定「谁在什么时刻触发」
   （任务创建、改负责人、每日定时扫描），属于下一轮工作，本轮不假装已支持。
2. **`page` 默认留空**（进小程序首页）。填小程序页面路径能深链到详情，但页面被重命名后
   会静默变成 41030 —— 要么同时加监控，要么保持为空。
3. **一次性授权的数量上限**由微信控制：单次 `requestSubscribeMessage` 最多 3 个模板 id，
   同一模板重复授权可以累积，但用户长时间不点「允许」就会一直停在 0。
4. **同名账号不发**：`users.name` 命中多个账号时跳过并记 warning（宁可不发，也不发错人）。
   历史脏数据的清理走「人员管理 → 归属映射」。
5. **`enabled` 与 `templateId` 两个字段都要看**：`templateId` 为空是「没配置」，
   `enabled=false` 是「配了但被停用」，页面文案不同；后端 `configured` 的口径是
   「至少有一条模板既配了 id、又没被停用」。
6. **用户改名后旧账本不会自动迁移**：账本按 `user_id` 存，改名不影响；但如果改名前的通知
   是按姓名解析的，解析失败的那次会记 warning 且不发 —— 需要给该员工补登记 `staff_aliases`。
7. **`test` 接口会真发消息**：已加 `throttle:6,1`，仍建议只在排障时使用。
8. **未绑定微信 = 永远收不到**：`users.wx_openid` 为空的账号一律 skipped。
   绑定入口在「我的 → 微信绑定」（`PUT /auth/wx-self-bind`），到期提醒也没用 —— 先绑。
